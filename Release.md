# Release

## Release Process

1. Update the project version where required.

2. Update release notes with the changes included in the release.

3. Run the project's tests.

4. Run linting and builds.

5. Review the generated changes.

6. Create a release commit using the project's Conventional Commit format.

7. Create the corresponding Git tag.

8. Publish the release through the project's configured release system.

## Release Notes

Each release should document:

- New features

- Improvements

- Bug fixes

- Breaking changes

- Dependency updates when relevant

## Pre-release Checklist

- [ ] Tests pass

- [ ] Linting passes

- [ ] Build succeeds

- [ ] Version is correct

- [ ] Release notes are updated

- [ ] No unintended files are included
